### 1. Maven Build Lifecycle

Maven follows a predefined build lifecycle consisting of different phases. Each phase performs a specific task, and running a later phase also runs the required earlier phases.

```text
compile
   ↓
test
   ↓
package
   ↓
install
mvn compile
Compiles the main Java source files from:
src/main/java
and places the compiled .class files in:
target/classes
It does not run tests, create a JAR/WAR, or install the artifact.
mvn test
Compiles the project and runs tests located in:
src/test/java
mvn package
Runs the required previous phases and creates the project's package, such as a JAR or WAR, inside target/.
mvn install
Runs the previous phases and installs the generated artifact and POM into the local Maven repository:
~/.m2/repository
On Windows:
C:\Users\<username>\.m2\repository
Maven Commands
Command	Purpose
mvn compile	Compile main source code
mvn test	Compile and run tests
mvn package	Compile, test, and create package
mvn install	Compile, test, package, and install locally
mvn clean package	Clean old output and create a fresh package
mvn build is not a standard Maven lifecycle phase.

### 2. Java Source and Target Versions
The Java compiler can be configured using source and target.
Source version controls which Java language syntax and features can be used.
Target version controls the version of Java bytecode generated by the compiler.
Source
  ↓
Language features

Target
  ↓
Generated bytecode
A newer JVM can generally run older Java bytecode, but an older JVM cannot normally run newer bytecode. This can result in:
UnsupportedClassVersionError
________________________________________
### 3. maven.compiler.release
The release option is a safer way to specify the Java version the application should target.
<maven.compiler.release>17</maven.compiler.release>
It checks:
•	Java language features
•	Generated bytecode version
•	Available public Java APIs
Therefore:
release
  ↓
Language level
+ Bytecode version
+ Available APIs

### 4. Character Sets and Encoding
A character set defines the characters that can be represented.
An encoding defines how those characters are represented as bytes.
Characters
    ↓
Character Set
    ↓
Encoding
    ↓
Bytes
Common encodings discussed:
•	UTF-8
•	UTF-16
•	ISO-8859-1
•	US-ASCII
UTF-8 supports Unicode and is compatible with ASCII for its first 128 characters.
Multiple encodings exist because of different languages, historical systems, storage limitations, and compatibility requirements.
Using the wrong encoding to read data can result in corrupted characters.
Maven encoding can be specified in pom.xml:
<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
<project.reporting.outputEncoding>UTF-8</project.reporting.outputEncoding>

### 5. Backward and Forward Compatibility
Backward compatibility means a newer system can support older software or data.
Forward compatibility means an older system can tolerate newer information.
For Java:
Older bytecode → Newer JVM
Generally works
Newer bytecode → Older JVM
Generally does not work
For example, if an application needs to run on Java 17, it should be compiled for Java 17 rather than compiling for Java 21 and expecting it to run on Java 17.

### 6. JUnit
JUnit is a Java testing framework used to create automated tests.
Important annotations:
@Test
@BeforeEach
@AfterEach
Important assertions:
assertEquals()
assertTrue()
assertThrows()
Tests are normally stored in:
src/test/java
and can be run using:
mvn test
Example:
import static org.junit.jupiter.api.Assertions.assertEquals;
import org.junit.jupiter.api.Test;

class CalculatorTest {

    @Test
    void addsTwoNumbers() {
        Calculator calculator = new Calculator();
        int result = calculator.add(2, 3);
        assertEquals(5, result);
    }
}
JUnit also supports features such as parameterized tests, nested tests, and test lifecycle management. It integrates with Maven, Gradle, and IDEs.
________________________________________
### 7. Unit Testing
Unit testing verifies a small unit of behavior, usually a method or class, in isolation.
Good unit tests are:
•	Automated
•	Repeatable
•	Fast
•	Independent
•	Focused
External dependencies such as databases, networks, or external services can be replaced with test doubles.
Unit tests help detect defects early and provide confidence when code is modified, refactored, or extended.
________________________________________
### 8. Integration Testing
Integration testing checks whether multiple components work correctly together.
It can detect problems involving:
•	Data flow
•	Interfaces
•	Configuration
•	Databases
•	Serialization
•	Network communication
•	External services
Unit Testing	Integration Testing
Tests small units	Tests multiple components
Usually isolated	Components interact
Usually fast	Usually slower
Tests local logic	Tests component interaction
Easier failure diagnosis	More complex diagnosis
Both types of testing are useful because individual components may work correctly while still failing when combined.
